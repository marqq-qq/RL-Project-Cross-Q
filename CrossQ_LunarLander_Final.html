What earns reward, and what ends a flight?¶

During flight, the lander earns the change in a shaping score based on distance, speed, tilt and leg contact. Gaining a contact adds 10, losing it costs 10. Main and side engines cost 0.30 and 0.03 times their power per step.

The shaping score weights distance, speed and absolute tilt by −100 each, and each leg contact by +10.

On a physical termination, the last reward is replaced. A sleeping body receives +100. Hull contact or a horizontal exit receives −100. Sleep wins a tie in the simulator code. An unfinished flight truncates at 1,000 steps. Its last observation can still supply a bootstrap value.

2 · Inside CrossQ¶

Martin Klimov · The actor maps eight observations to a squashed Gaussian over two controls. The two critics each estimate the soft return of a state–action pair. CrossQ retains SAC’s replay buffer, entropy objective and smaller-of-two critic target.

Recorded state + recorded action ───┐
                                    ├── 256 rows ──► each online critic
Successor state + fresh actor action ┘                     │
                                            split its outputs by row
                                              ↙                  ↘
                                      128 current Qs       128 successor Qs
                                      fit both critics     form a fixed target

Replayed actions came from earlier behavior. Successor actions come from today’s actor. Computing statistics over their joint batch puts both halves on a common scale. This lets CrossQ bootstrap with the online critics, without maintaining separate slowly averaged target critics.

The two objectives¶

Draw a successor action a′ from the actor at s′. Let d = 1 for a true termination, and d = 0 otherwise.

Critic target   y = r + γ(1 − d) [min(Q₁(s′,a′), Q₂(s′,a′)) − α log π(a′|s′)].

Critic loss   Take half the sum of the two batch mean squared errors against the detached target y.

Actor loss   Minimize the batch mean of α log π(a|s) − min(Q₁(s,a), Q₂(s,a)) for fresh actor actions. Higher predicted value and greater policy entropy both help. The implementation learns the temperature α. It freezes critic normalization statistics during the actor update.

See the effect of joint normalization¶

One feature for replay actions has values 0, 2. The same feature for successor actions has values 8, 10. What information disappears if we normalize each half separately?

current = torch.tensor([[0.], [2.]])
successor = torch.tensor([[8.], [10.]])
bn = torch.nn.BatchNorm1d(1, affine=False, track_running_stats=False)
separate = torch.cat([bn(current), bn(successor)])
mixed = torch.cat([current, successor])
joint = bn(mixed)
print("Separate scales:", separate.flatten().numpy().round(3))
print("Shared scale:   ", joint.flatten().numpy().round(3))
print("Mixed mean and population variance:", mixed.mean().item(), mixed.var(unbiased=False).item())
assert joint[1] < 0 < joint[2]

Separate scales: [-1.  1. -1.  1.]
Shared scale:    [-1.213 -0.728  0.728  1.213]
Mixed mean and population variance: 5.0 17.0

The two separate pairs both become approximately [−1, +1]. On the shared scale, both replay values fall below the mixed mean. This example isolates one feature. SB3-Contrib uses BatchRenorm inside networks, with an initial batch-normalization phase, running statistics and later training-mode corrections. Inference uses stored statistics, so the pilot can act on a single observation.

3 · One numerical update¶

Malik Nurullin · Illustrative one-transition critic update. Hold the target fixed and represent one current Q estimate by a scalar parameter. The next critics predict 3 and 4. The actor’s sampled next-action log density is −0.5.

Before running the cell, predict whether Q should rise or fall when its present value is 2.

r, gamma, done = 1.0, 0.9, 0
alpha, log_prob = 0.2, -0.5
next_q = torch.tensor([3., 4.])
q = torch.nn.Parameter(torch.tensor(2.))
before = q.item()
with torch.no_grad():
    entropy_term = -alpha * log_prob
    target = r + gamma * (1 - done) * (next_q.min() + entropy_term)
td_error = target - q
loss = 0.5 * td_error.square()
print(f"Entropy term {entropy_term:+.2f}   |   target {target:.3f}   |   TD error {td_error.item():+.3f}")
print(f"One critic's half-squared loss: {loss.item():.5f}")

Entropy term +0.10   |   target 3.790   |   TD error +1.790
One critic's half-squared loss: 1.60205

The target is 1 + 0.9 × (3 + 0.1) = 3.79. The TD error is 3.79 − 2 = 1.79. If d were 1, the target would be the immediate reward of 1. Now take one gradient step.

optim = torch.optim.SGD([q], lr=0.1)
optim.zero_grad()
loss.backward()
gradient = q.grad.item()
optim.step()
after_loss = 0.5 * (q.detach() - target).square()
print(f"Gradient {gradient:+.3f}   |   Q {before:.3f} → {q.item():.3f}")
print(f"Loss against the same target: {loss.item():.5f} → {after_loss.item():.5f}")
np.testing.assert_allclose([target.item(), td_error.item(), loss.item(), gradient, q.item()],
                           [3.79, 1.79, 1.60205, -1.79, 2.179], atol=1e-6)

Gradient -1.790   |   Q 2.000 → 2.179
Loss against the same target: 1.60205 → 1.29766

The negative gradient moves Q upward by 0.179. Full CrossQ does this across two neural critics and a minibatch using Adam. Its critics share current/successor normalization statistics, and the next actions and entropy term come from the actor.

What the training loop did¶

After warm-up, uniformly sample 128 transitions from replay. The stored action trains the current Q. A fresh action at the successor state supplies the soft target. This reuses transitions collected by older policies.

These short excerpts show the actual construction and block-level calls from train.py. The loop advances the same model for each block.

model = CrossQ("MlpPolicy", env, seed=TRAIN_SEED, device="cpu", **config)
model.learn(total_timesteps=n, reset_num_timesteps=False, callback=callback, log_interval=None)
evaluation = [episode(validation, s, model) for s in VALIDATION_SEEDS]

Every 10,000 steps, the script saves a checkpoint and measures mean original return on ten validation seeds, 4100–4109. Adam uses actor/critic betas (0.5, 0.999). Temperature starts at 1 with target entropy −2. BatchRenorm uses momentum 0.01, ε = 0.001 and a 100,000-call warm-up. The latest replay buffer and optimizer state support resuming. Fifty other seeds, 8200–8249, are reserved for the frozen policy’s test.

Result. CrossQ landed on 48/50 test seeds, with two timeouts. Random actions produced 30 hull crashes and 20 horizontal exits. The mean paired gain was +492.72 points. A 95% bootstrap interval resampling whole seed pairs was +459.22 to +527.03.

Scope. This result describes one saved policy at default gravity with wind disabled. The three training configurations shared one seed. Independent training seeds and a matched-budget SAC comparison would be needed to estimate training variability and isolate CrossQ’s contribution.
